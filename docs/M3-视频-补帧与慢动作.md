# 视频管线：超分 / 补帧 / 慢动作 / 动态模糊 / SDR→HDR

一个 App 两套能力：图片走 `App/UpscaleEngine.swift`，视频走 `App/VideoEngine.swift` + `App/VideoView.swift`，
`App/RootView.swift` 用 `TabView` 把两者并到同一个壳里。

## 1. 数据流

```
相册 / 文件 App
   └─ PickedVideo(Transferable) 或 .fileImporter
        └─ VideoEngine.load(url:)  拷贝到临时目录（security-scoped 资源先 startAccessing）
             └─ AVURLAsset 读 naturalSize / preferredTransform / duration / nominalFrameRate

VideoEngine.start()
   └─ VideoSettings 快照（不可变，跨线程）
        └─ VideoRenderer.render(...)  跑在 DispatchQueue.global(.userInitiated)
             ├─ AVAssetReader + AVAssetReaderVideoCompositionOutput
             │     videoComposition = AVVideoComposition(propertiesOf: asset)   ← 正向帧
             ├─ 逐帧解码 → CVPixelBuffer → Pix.cgImage(from:)
             ├─ makeFrame(cg)  目标尺寸 RGBx：
             │     · 快速：CGContext 高质量重采样
             │     · AI  ：先缩到 aiLongEdge，再 TileEngine.upscale 出 4×，最后缩到目标
             ├─ FrameOps.flow(from:to:)  Vision 光流（长边 ≤960 算，位移量按比例放大）
             ├─ 每对相邻帧之间补 perPair 帧：synthesize() 双向 warp 后按 t 融合
             ├─ 动态模糊：同一时刻前后 blurSamples 个采样加权平均
             └─ AVAssetWriterInputPixelBufferAdaptor.append  →  HEVC .mp4
```

音频：`keepAudio` 为真时用第二个 `AVAssetReaderTrackOutput`（`outputSettings: nil`）直读，
对应 `AVAssetWriterInput(mediaType: .audio, outputSettings: nil)` 原样透传，不解码不重编码。

## 2. 参数语义（`App/VideoEngine.swift`）

| 选项 | 取值 | 影响 |
|---|---|---|
| `InterpMode` | off / ×2 / ×4 | `factor` = 1/2/4，输出帧率 = `clip.fps × factor`（上限 240） |
| `SlowMode` | 原速 / 0.5× / 0.25× | `factor` = 1/0.5/0.25，拉长时间轴 |
| `BlurMode` | off / 轻 / 强 | `samples` = 1/3/5，多采样叠加，`spread = 0.35 / max(2, perPair)` |
| SDR→HDR | 关闭 / HLG，强度 0–100% | 10-bit P010/HEVC，BT.2020 primaries/matrix + BT.2100 HLG transfer；亮度在编码前由 SDR 线性光进行 reference-white 映射与可调 highlight shoulder |

关键推导：**每对原始帧要输出多少帧** `perPair = round(interp.factor / slow.factor)`。

- 只补帧 ×2 → perPair 2，8 秒 30fps 的片子出 480 帧、60fps、时长不变；
- 只慢动作 0.5× → perPair 2，出 480 帧、30fps、时长翻倍；
- 补帧 ×2 + 慢动作 0.5× → perPair 4，出 960 帧、60fps、时长翻倍。

PTS 由 `outIndex / outFps` 重算（timescale 600），所以慢动作不需要额外改时间轴。

## 3. 为什么慢动作没有声音

慢动作改变的是**时长**，音轨要么拉伸（会变调）要么重采样（要额外算法），
这一版直接 `keepAudio = slow.factor > 0.999`，慢动作时丢弃音轨并在 UI 里写明。
只补帧不改时长时音轨原样透传。

## 4. 性能闸门

| 场景 | 输出上限 | 原因 |
|---|---|---|
| 只放大 | 3840 长边 / 830 万像素 | 单帧只是重采样，成本低 |
| 补帧 或 慢动作 | 1920 长边 / 210 万像素 | 每对帧要多算光流 + perPair 次合成 |
| 再加动态模糊 | 1440 长边 / 140 万像素 | 每次再乘 blurSamples 次采样 |

光流在长边 ≤960 上算，位移按 `tw / flow.w` 放大回目标尺寸；这样单帧光流约 10–20ms，
不会把补帧拖成幻灯片。超过 5400 帧会给「先剪短」的提示。

## 5. 画面质量取舍

- **光流补帧的边界情况**：大面积遮挡、闪烁、快速横移时，双向 warp 会出现轻微拖影或撕裂。
  这是光流法的固有短板（RIFE 这类模型也一样，只是概率低一点），不是 bug。
- **AI 逐帧超分**：每帧都走一次分块推理，`aiLongEdge = min(1280, max(384, 目标长边 / 4))`。
  10 秒 30fps = 300 帧，每帧几十个 256×256 分块，实测量级是几分钟，所以默认是快速放大。
- **不要连续二次放大**：快速放大后再 AI 超分一次，只会把插值出来的模糊再放大一遍。

## 6. SDR → HDR 实现与验证范围

视频 HDR 打开时，处理链是：SDR RGB8 → sRGB/BT.709 EOTF 还原线性光 → luminance shoulder（滑杆控制）→ 线性 Rec.709 转 Rec.2020 → 分别对 R′G′B′ 分量应用 HLG OETF → 从 HLG 编码分量计算 BT.2020 Y′CbCr 4:2:0 → video-range P010 10-bit → HEVC。导出声明 BT.2020 primaries/matrix 与 BT.2100 HLG transfer；关闭时继续用 8-bit BGRA SDR / Rec.709。P010 亮度码值用 64–940，色度用 64–960，10-bit 左对齐写入 16-bit word，带固定空间 4×4 dithering 降低色带。

### 映射意图

- SDR diffuse white 以 HLG scene/reference white 0.75 标定，不把普通白色直接顶到 HLG 100% 信号峰值。
- 高光 shoulder 使用 `u = clamp((Y−0.70)/0.30, 0, 1)`、`k = u²(3−2u)`、`Y' = Y + strength × 0.30 × k²`；低于 70% scene white 保持不变，strength=0 仍只做 HLG transfer / 色域变换。
- 这是由 SDR 推导的“显示增强/高光扩展”，不是从被剪切的 SDR 里恢复不存在的纹理，也不是 AI 语义 relighting；观感须在支持 HLG 的设备上评估。

### 可复现数值验证

`python scripts/verify_hdr_math.py` 检查 HLG 曲线单调/有限，Rec.709→2020 白点中性，高光强度随档位单调，黑色保持黑色，以及 P010 luma/chroma legal code ranges。它只验证公式与映射数值，不验证 Swift 编码器是否输出有效 Main10 bitstream、iOS 相册/播放器色彩管理或主观效果。当前没有真机 HDR 屏幕验证。

Apple 文档： [AVVideoColorPropertiesKey](https://developer.apple.com/documentation/avfoundation/avvideocolorpropertieskey)、[BT.2100 HLG transfer function](https://developer.apple.com/documentation/avfoundation/avvideotransferfunction_itu_r_2100_hlg)、[AVVideoTransferFunctionKey](https://developer.apple.com/documentation/avfoundation/avvideotransferfunctionkey)、[AVVideoColorPrimariesKey](https://developer.apple.com/documentation/avfoundation/avvideocolorprimarieskey)、[Setting color properties for a specific resolution](https://developer.apple.com/documentation/avfoundation/setting-color-properties-for-a-specific-resolution)。

## 7. 与 Time Cut 的差距（诚实版）

| 能力 | 本版 | Time Cut |
|---|---|---|
| 4× AI 超分（图片/视频帧） | ✅ | ✅ |
| 补帧到 60/120fps | ✅ 光流法 | ✅ 模型法，遮挡处更稳 |
| 慢动作 | ✅ 0.5× / 0.25×（无音轨） | ✅ 带音高修正 |
| 动态模糊 | ✅ 多采样近似 | ✅ 快门角度建模 |
| 分辨率/时长限制 | 有（内存与耗时） | 有（免费版限制更狠） |
| 订阅 / 上传 | 无，全本地 | 有内购 |
