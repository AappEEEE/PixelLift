# M5 分片渲染 · 断点续传 · passthrough 拼接

## 为什么分片

视频增强是「逐帧推理 + 重编码」，10 秒 1080p 的片子就要几十秒到几分钟。中途锁屏、切后台被系统回收、
手滑点取消，整条片子就从 0 重来。分片把损失限定在最后 20 秒。

## 实现

| 部分 | 位置 | 做法 |
| --- | --- | --- |
| 切片 | `VideoRenderer.segmentCount(duration:)` | 源时间按 20 秒切片，`ceil(duration / 20)` |
| 单片渲染 | `VideoRenderer.render(... timeRange: ..., baseFrames: ...)` | `AVAssetReader.timeRange` 限定解码区间；写入器 PTS 从 0 重新计 |
| 调度 | `VideoRenderer.renderSegmented(...)` | 逐片调用；已完成的片直接跳过 |
| 拼接 | `VideoRenderer.stitch(_:dest:)` | `AVMutableComposition` 顺序 `insertTimeRange`，`AVAssetExportPresetPassthrough` 导出 |
| 进度 | `JobStore` | `Documents/PixelLiftJobs/<sha256>/job.json` 记 `done: [Int]` |

分片文件命名 `seg-0000.mp4`，与 `job.json` 同目录。任务完成或主动丢弃时整个目录删除。

## 任务指纹

```swift
[source.path, "1920x1080", "60.000", "ai500", "p2b1", "sdr"].joined(separator: "|")
```

再取 `SHA256` 前 24 个十六进制字符。尺寸、帧率、AI 开关、补帧/模糊档位、HDR 开关任何一项变了，
就是不同任务，不会把上一条片子的分片错拼进来。

## 为什么不给 HDR 分片

拼接走 `AVAssetExportPresetPassthrough`，不重编码，理论上是无损的。但 10-bit HLG 的
色彩元数据（primaries / transfer / matrix）保存在 track 与 sample 描述里，不同分片在
composition 里合并时是否被完整保留，没有真机可验证。既然 HDR 是本 App 的主打能力，
选择「HDR 单条输出、SDR 才分片」而不是赌元数据。

## 已知边界

- 分片边界会多出一帧（每片收尾写一次 `lastBuf`），20 秒 30fps 约 600 帧里多 1 帧，观感不可见。
- 补帧/模糊跨分片时不连续：每片的首帧没有「上一帧」可参考，边界处少合成 1 帧。
- 单片失败会让整单失败，已完成的片保留，重进可继续。
- 拼接是 passthrough，分片必须同编码参数；改设置会重新生成新任务而不是复用旧片。

## 真机验收

1. 10 分钟以上 SDR 素材，跑到 30% 左右点取消，确认「有未完成的分片任务」卡片出现。
2. 点「接着做」，确认从断点继续而不是从 0 开始。
3. 完成后确认时长与源片一致（±1 帧/片）、首尾不黑屏、无音画不同步。
