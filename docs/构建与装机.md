# 构建与装机（无 Mac 版）

全程只需要一台 Windows + 一个 iPhone + 一个 GitHub 账号。

---

## 一、把仓库推到 GitHub

```powershell
cd "D:\AI Projects\v2rayN移植"
git init
git add .
git commit -m "PixelLift M1: on-device image super resolution"
gh repo create PixelLift --public --source=. --push
```

> **建议 public**：GitHub 的 macOS runner 私有仓库按 **10 倍** 计费（免费额度 2000 分钟 → 实际只有 200 分钟），public 仓库免费无限。代码里没有密钥，公开无风险。

---

## 二、构建（不需要人点批准的情形下会直接跑）

push 之后打开 `https://github.com/<你的账号>/PixelLift/actions`。

### 需要你手动点批准时，点哪里

| 你看到的 | 点哪里 | 为什么会这样 |
|---|---|---|
| 页面顶部黄色条：**"This workflow requires approval from a maintainer"** / 某个 run 显示 **Waiting for approval** | 点右侧 **Approve and run**（或打开该 run → 右上 **Review pending deployments / Approve**） | 首次运行、或 workflow 由他人/fork 提交时，GitHub 默认要维护者批准 |
| run 里显示 **"Waiting"** 且提示 environments | 打开该 run → **Review deployments** → 勾选环境 → **Approve and deploy** | 仓库配了带 reviewer 的 Environment；本项目没有，若你看到就是自己加的，删掉即可 |
| run 失败提示 **"Resource not accessible by integration"** | Settings → Actions → General → **Workflow permissions** 选 **Read and write** → Save | 默认 token 只读 |
| 一直是 **Queued** 不动 | ① 私有仓库 macOS 分钟用尽；② Actions → General 里 concurrent 限制 | 换 public 仓库 |
| Actions 页面提示 disabled | Settings → Actions → General → 选 **Allow all actions** | 组织/账号策略关掉了 Actions |

正常情况下：**public 仓库 + push 到 main = 自动跑，零点击**。

构建成功后在 run 页面底部 **Artifacts** 下载 `PixelLift-unsigned-ipa`，解压得到 `PixelLift-unsigned.ipa`。

一次构建大约 8–15 分钟（首次要装 torch 并转换模型，之后走缓存约 5 分钟）。

## 三、装到 iPhone（免费 Apple ID）

### 路线 A：Sideloadly（最省事，推荐）

1. 电脑装 [Sideloadly](https://sideloadly.io/) 和 [iTunes](https://www.apple.com/itunes/)（需要它的驱动）。iPhone 用数据线连上，点"信任此电脑"。
2. 打开 Sideloadly，把 `PixelLift-unsigned.ipa` 拖进 **IPA** 框。
3. **Apple ID** 填你的 Apple ID（可以用小号），它会用你的免费开发者证书签名。
4. 点 **Start**，输入 Apple ID 密码（如开了双重认证，用 App 专用密码）。
5. 装好后进 iPhone：**设置 → 通用 → VPN与设备管理 → 开发者APP → 信任你的 Apple ID**。
6. 打开 PixelLift。首次选图会问相册权限，允许。

**限制**：免费证书 **7 天** 过期，过期后 App 打不开，用 Sideloadly 重签一次即可（不用重新构建，ipa 留着就行）。

### 路线 B：AltStore / SideStore

装 AltServer（Windows 版），用 AltStore 导入 ipa。7 天续签可以在同一 Wi-Fi 下自动完成，比手动重签省心。SideStore 支持完全脱离电脑续签，但配置麻烦一些。

### 路线 C：有付费开发者证书时

用 zsign 直接签（不需要 Mac）：

```powershell
zsign -k cert.p12 -p 证书密码 -m app.mobileprovision -o PixelLift-signed.ipa PixelLift-unsigned.ipa
```

再用 Sideloadly「IPA 已签名」模式或 `ideviceinstaller -i PixelLift-signed.ipa` 安装。有效期 1 年。

> 本项目**不需要**任何特殊 entitlement，所以免费签名和付费签名在功能上没有区别——只有有效期不同（7 天 vs 1 年）。

## 五、常见问题

**Q：为什么大图会先缩到 1024 长边？**
4× 模型的输出是输入面积的 16 倍。1024×768 输入 → 4096×3072 输出已经吃掉约 50MB 缓冲。手机上必须先控制输入尺寸，再用高质量 Lanczos 放到目标分辨率。这是移动端的物理限制，不是偷懒。

**Q：8× 是真的 8 倍细节吗？**
不是。模型原生 4×，8× 是"4× 重建 + Lanczos 再放大"。想更接近真实 8×，得用 Real-ESRGAN x8 或多级 4× 叠加（会慢 4 倍，M2 再谈）。

**Q：能不能处理视频？**
M1 只做图片。视频要接 `VTFrameRateConversion` 和分片暂停续传，是 M2 之后的事。

**Q：为什么不用系统自带的 `VTSuperResolutionScaler`？**
它要求 iOS 26+ 且需要真实视频帧缓冲管线，M1 用 Core ML 跑单图更直接、可移植（同样代码以后能复用到 macOS）。M2 做视频时再接它。

**Q：发热/掉电？**
走 Neural Engine，连续处理十几张会明显发热降频，属正常。插电使用体验最好。

## 六、CI 失败时看哪里

| 失败步骤 | 大概率原因 | 处理 |
|---|---|---|
| `Install converter deps` | 依赖版本冲突 | 日志里搜 `ERROR:`；本项目已 pin `numpy<2` + `torch==2.4.1` + `coremltools==8.1` |
| `Convert Real-ESRGAN weights` | 权重下载失败 / state_dict 键不匹配 | 会打印 `Missing key(s)` 或 HTTP 错误，把日志发我 |
| `Generate project` | `project.yml` 语法 | 报错行号直接指向那一行 |
| `Archive` | Swift 编译错误 | 搜 `error:`，把第一处发我 |
| `Package unsigned IPA` | 归档路径变了 | 日志里 `ls` 会列出真实路径 |
